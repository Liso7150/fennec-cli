# Changelog

All notable changes to fennec-cli, the Rust command-line launcher and front door for
the Fennec suite.

The sections below carry the published tag each change actually shipped in
(`Liso7150/fennec-cli`, `v0.1.0` … `v0.9.0`). An earlier revision of this file
numbered the same history on a 1.x/2.x ladder that was never published; those tags
still exist locally (`v1.2.0` … `v2.0.0`) and each one points at the same commit as
a published `v0.x` tag — local `v2.0.0` and published `v0.9.0` are the same commit.
`v0.2.0` was never released here (the ladder goes `0.1.0` → `v0.3.0`), and `v0.7.0`
carries only version-string edits over `v0.6.0`. Dates are the GitHub release
publish dates.

## [Unreleased] — 1.0.0 in preparation

Nothing at 1.0.0 is published. The newest release here is `v0.9.0`
(2026-11-11T19:29:02Z). Measured on the working tree: **73 tests passed / 0 failed
across 7 suites** (`cargo test --release --offline`). Counts come from
`benchmarks/artifacts/hub/RESULTS.json` (updated 2026-11-24T07:29:28Z) and are
generated by the hub (`python benchmarks/results.py` in the suite root), not
hand-maintained. Two console binaries (`fennec`, `fennec-rs`) and no Python package
left in the repo.

### Added
- The launcher itself is Rust: `fennec` is built from `src/launcher.rs`, so the
  command starts without paying for an interpreter
- Rust CLI binary (`fennec-rs`), moved here from fennec-core; CI builds it against
  the fennec-core crates
- `fennec agent <verb>` fronts the coding-agent backend through
  `fennec_client::coding_agent::CodingAgentClient`: `status`, `tasks`, `task <id>`,
  `chat <message>`, `agents` and `repos`, each printing what the backend answers
  rather than a guess
- `src/updater.rs`: `fennec update` checks `Liso7150/fennec-cli` GitHub releases,
  downloads the per-platform asset named by `Platform::asset_name("fennec-cli")` and
  verifies it against a SHA-256 checksum before applying; `--experimental` reads the
  branch commit instead, and `--binary` skips the suite-checkout pull
- CI Rust CLI build expanded to macOS and Ubuntu; the CI lane checks out
  fennec-economy alongside fennec-core
- README hero published

### Changed
- Read the model from `FENNEC_MODEL` first, then the backend and cache knobs, all
  pinned under `FENNEC_*` names only
- The repo root is the crate: the CPython package `fennec_cli/`, its
  `pyproject.toml`, `tests/test_cli.py` and the Python CI lane are deleted, and their
  behaviour is covered by the 73 Rust checks above. Build it with
  `cargo build --release`; nothing here is pip-installed any more.
- The engine probe is Fennec-only: it looks for a native `fennec` binary under
  `target/release` (then `target/debug`, then the root), and the legacy-engine
  launcher probe and the `COLI_*` pinning are gone from the launcher's own
  environment — the only `c/coli` paths left are negative fixtures in
  `tests/launcher.rs` proving the probe refuses them. When nothing is found the error
  names the remedy — build the engine with `cargo build --release` or run the Fennec
  environment installer — and exits 2
- `tests/cli_surface.rs` drives the engine passthrough with a native engine stub
  compiled by `rustc` at test time (it reports its arguments and the pinned
  environment it received) instead of a Python script fixture; the launcher's
  legacy-engine doctor test was deleted with the legacy path
- Crate moved to Rust edition 2024 with `rust-version = 1.85`; the `kernel32` extern
  block in `src/mem.rs` was made `unsafe` for the new edition
- `fennec update` pulls the hub, which is a suite checkout now, and follows the
  flattened core layout plus the crates the binaries depend on
- `fennec-rs` points at `fennec-core/src` and ignores the workspace target dir

### Removed
- The `coli` alias binary (`src/bin/coli.rs`): `fennec` is the only launcher command,
  so `src/bin/` builds two names instead of three

### Fixed
- `fennec update` refuses arguments that are not `--experimental` or `--binary`
  instead of silently accepting them, matching every other verb

## [0.1.0] - 2026-11-10

The first published release. It carries the pre-tag history below.

### Added

- Config-driven launcher with tests and a CI matrix (3 OS × 3 Python)
- Features documented in the README

### Fixed
- `--help` and `--version` work without an engine checkout
- Essential Windows env kept for the subprocess CLI test
